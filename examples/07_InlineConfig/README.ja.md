# 07_InlineConfig

> English: [README.md](README.md)

開始する箇所でタスク設定を組み立てるサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [07_InlineConfig.ino](07_InlineConfig.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<ESP32TaskKit.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `inlineCfgTask.startLoop(...)` — trueで継続、falseで終了する繰り返し処理を開始します。生成の成否と参照するコンテキストの寿命を確認します。

## APIの使い方と注意点

タスクが終了するまで `Task` オブジェクトとC形式の引数領域を生存させます。組み込む際は `start()`／`startLoop()` の戻り値を確認します。ログが出ない原因は周期ではなく生成失敗かもしれません。

ループコールバックはtrueで継続、falseで終了します。`requestStop()` は協調的な停止要求で、長い処理を即時に中断しません。C形式では処理自身が停止フラグを確認します。

`startLoop()` の周期はmsですが、FreeRTOSの生APIはtickを使います。ESP32のスタック容量とHigh Water Markはbyte単位で、既存の出力ラベルにwordsとあっても単位は変わりません。診断機能はコアの設定次第なので、統計を使えないこととタスクの失敗を区別します。

既定サイズやビルド条件の表は複製せず、ルートのAPI説明を参照します。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text
[+%lu ms] inline cfg task
```

## この例を変更するとき

すぐに実行するLambdaがTaskConfigを返し、別のLambdaが繰り返し処理です。ESP32のstackSizeはbyte単位で、古いword表記の解釈はしないようにします。

## 確認と問題の切り分け

開始する箇所でタスク設定を組み立てることを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
